### 追加実験 E-S1b（2026-11-09・入力の再実行による故障注入）

全文確認が出した懸念「本評価の中で、関係だけが検出しかつ報告数値を動かした故障が1件も無い」に対して
実施。$0・ローカル・約75分（60 run × 5 水準）。**結果は成功**（§5.1・Table 6）。

**着手前に分かったこと**：0/168 は抽選の結果ではなく**構造**だった。`headline()` は run table だけを読み、
表外の3 operator（`input_perturb`・`npz_perturb`・`npz_swap`）はいずれも `rows` を触らない。
原理的に動かせない。この一事で、必要な実験の形が決まった（記録を編集するのでなく**再実行**する）。

**失敗を4回した。全部同じ型**：注入が意図した形になっているかを確認せず、返ってきた数字を結果として読んだ。

| # | 症状 | 真因 | 気づいた手段 |
|---|---|---|---|
| 1 | 見出しが5件動いた（成功に見えた） | 再実行を `lightning_cpu/double` でやった。committed は `lightning_gpu/single` | 対照が `backend` の2値で発火したのを追った |
| 2 | 何も起きない | 摂動した銘柄が対象インスタンスに不在（50銘柄から無作為＝的中率約1/4） | `input_digest` を直接比較した |
| 3 | 何も起きない | `DERIVED_DIR` だけ差し替え、価格キャッシュが先に読まれた。ハーネスは `_loader_dirs` で**両方**を差し替えている | 同上 |
| 4 | 宣言的対照が `fk` で発火 | 6ペナルティ中2つしか再実行せず、残り40行が旧 digest を保持 | 発火メッセージの行数40を数えた |

1 は「成功」として、2・3 は「結果」として、4 は「失敗」として、それぞれ誤読しかけた。
**数字自体は毎回正しかった** — 関係も対照も、与えられた記録に対して正しい答えを返していた。
壊れていたのは注入手順だけ。

**対策（実装済み）**：ドライバに注入ゲートを入れ、**壊して落ちることを確認**した。

- 不変列（backend・precision・steps・p・shots・optimizer）が committed と違えば**中断**
- インスタンスを部分的にしか覆っていなければ**中断**
- 入出力が変化したかは**中断せず報告**（δ が小さい場合はそれ自体が測定対象）

ユーザ指摘：「入力が届いたかの検査は構造上まず落ちない」→ 正しい。弱い版（digest が変わったか）は
共有銘柄から選ぶ修正で自動的に満たされる。**強い版（出力が実際に動いたか）**に置き換えた。
δ 掃引ではこちらが本体で、「digest は変わったが解は動かない」を検出する。

**結果の読みどころ**：宣言的対照は**全5水準で沈黙**（δ=1e-1＝入力の10%改竄でも0件）。
E-S1 本体の「検出は magnitude に依存」（1e-9 で47%、1e-6〜1e-1 で79–81%）と対照的で、
**表の外では magnitude が効かない**。境界を決めるのは大きさでなく記録の及ぶ範囲、という主張の直接の対比。
加えて δ=1e-9 では関係が検出するのに見出しは動かない＝**報告値が壊れる前に捕まえる**。

**道具の教訓**：`check_tables.py` の表番号繰り下げを正規表現でやって `chk(`/`chks(` を壊した。
git から復元してやり直した。**連番の振り直しは、置換後に必ず `ast.parse` と全文検査を通す。**
unbound 宣言のようにタプル内に埋まった番号は、呼び出し形の正規表現では拾えない。

## 投稿前の弱点対応（2026-11-09 午後）

AI 査読が挙げた弱点 5 つのうち、データと GPU 機だけで直せる 3 つを直した（$0・約 2.5 h の計算）。
- 「1記録」→ E-S1 全部を兄弟記録 2 本で再実行（`--record`）。検出パターンは同じ。未検出 3 本は
  「誰も読まない共分散セル」で、digest の定義どおり。**弱点を潰しに行った測定が、設計の限界を
  1つ正確に言語化した**（digest は run が読んだ入力の束縛であって、ファイルの束縛ではない）。
- 「存在証明」→ Table 6 を第2インスタンス対で。発火する関係の組が対に依って違い（`identities` 対
  `state-recompute`）、何を読む関係かが見えた。率にはしていない。
- 「境界が自明」→ §5.1 の冒頭段落で非自明な 3 結果を先に置いた。
**道具の教訓**：バックグラウンドのチェーンは `PYTHONUNBUFFERED=1` で起動する（さもないと status の
STALLED 判定が誤る）。`pkill -f` のパターンは自己一致しない形（`[e]s1_…`）にする。全列 0 の表の列は
キャプションに移す（acmsmall で 8 列は見出しが重なった）。

## 査読ラウンド2（2026-11-09 22:20 → 11-10）

AI 査読の M1（部分集合からの一般化）と M2（tier がデータアクセスの ablation になっていない）は**正しく、同根**だった。
一般化の誤りは、私が「見出しを動かした 52 件」で境界を言い切ったこと。直し方は「表の外だけ」を撤回して
節単位で測り直すこと以外に無く、約 2.5 時間の再生で済んだ。結果は論文を弱めず**鋭くした**：
対照との差の大半は「表に無い値」ではなく「宣言しなかった期待」で、これは validation library でも書ける——

**教訓**：検査の名前単位で数えると、節が異なるファイルを読む検査が集計を汚す。finding に出所を付けるのは最初からやるべきだった。
**道具**：引数名を局所変数で**上書き**して結果列を壊した（`gate`）。評価関数の引数と同名の変数を作らない。
表番号の振り直しは「キャプション行」と「本文参照」を別々の正規表現で当てると二重適用になる——負の後読みで除外。
